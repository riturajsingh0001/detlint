# Schemas

Schemas tell detlint which fields a log source actually has. They power:

- unknown-field detection and “did you mean” suggestions,
- case-mismatch warnings,
- enum validation (`unreachable`),
- integer type checks.

## Bundled schemas

| Name | Product / service | Contents |
|---|---|---|
| `windows_security` | `windows` / `security` | Security event log, process creation, logon, object access |
| `windows_powershell` | `windows` / `powershell` | PowerShell operational and script block logging |
| `linux_auditd` | `linux` / `auditd` | auditd execve and syscall records |
| `aws_cloudtrail` | `aws` / `cloudtrail` | CloudTrail management events |
| `okta` | `okta` / `okta` | Okta System Log authentication and admin events |

List them with:

```console
detlint schema list
```

## Format

A schema is a YAML mapping:

```yaml
name: custom_app
product: custom
service: app
category: authentication
description: Custom application authentication events

fields:
  - name: EventID
    type: int
    required: true
    description: Event identifier
    enum: [1, 2, 3]

  - name: User
    type: string
    required: true

  - name: SourceIp
    type: ip

eventids:
  - id: 1
    name: Login
  - id: 2
    name: Logout
```

`name` defaults to the file stem. At least one of `product`, `service`, or
`category` is required; otherwise detlint cannot match the schema to a rule.

### Fields

`fields` may be a list of mappings, or a mapping of field name to type:

```yaml
fields:
  EventID: int
  User:
    type: string
    required: true
    description: Account name
```

Field keys:

| Key | Meaning |
|---|---|
| `name` | Field name (required in list form) |
| `type` | `string`, `int`, `float`, `bool`, `ip`, `datetime`, `guid`, or `any` |
| `required` | `true` when every event should contain the field |
| `description` | Documentation shown by future tooling |
| `enum` | Allowed values, as a YAML list |

Types are used for static validation. `int` fields reject non-numeric values,
and `enum` fields reject values outside the list. String modifiers such as
`|contains` bypass enum checks because they are not exact comparisons.

### Event IDs

`eventids` is optional and documents known identifiers:

```yaml
eventids:
  - {id: 4688, name: Process Creation}
  - 4624
```

The list is informational for now; enum validation on the `EventID` field is
what makes impossible event IDs a hard error.

## Custom schemas

Point detlint at a directory (or one file) with `--schema`:

```console
detlint check rules/ --schema schemas/
detlint schema list --schema schemas/
```

Every `*.yml` / `*.yaml` under the directory is loaded. Hidden directories are
skipped. When `--schema` is set, the bundled schemas are not used, so include
copies of any bundled schemas you still need.

## Matching

A rule's `logsource` is matched against every schema. Product, service, and
category must match case-insensitively when the rule specifies them. The best
match wins; a schema with a matching service beats one without. If no schema
matches, the `typos` pass emits a warning saying fields cannot be validated.

A rule with no logsource is not matched against any schema and only gets the
metadata warning.

## Learning a schema

`detlint schema learn` infers a schema from JSONL samples:

```console
detlint schema learn logs/app.jsonl --name custom_app --product custom --service app
detlint schema learn logs/ --name custom_app --product custom --service app -o schemas/custom_app.yaml
```

The learner:

- flattens nested objects into dotted field names,
- infers `int`, `float`, `bool`, or `string` from the values,
- marks a field `required` when it appears in every record,
- records an `enum` when a field has at most 15 distinct, non-null values,
- sorts fields by frequency and then name.

The output is ordinary schema YAML, so you can edit it and commit it next to
your rules.

```yaml
# Generated by detlint schema learn
name: custom_app
product: custom
service: app
fields:
  - name: EventID
    type: int
    required: true
    enum: [1, 2, 3]
  - name: User
    type: string
    required: true
```
